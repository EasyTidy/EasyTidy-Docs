title: 高级流程
description: 使用多来源、条件组合、多个文件操作和后置整理任务构建高级流程。
---

“高级流程”用于把多个来源、条件和文件操作保存在同一条流程中，并可在主体操作结束后继续运行已有的普通整理任务。它适合需要统一筛选后执行多种操作，或需要把多个现有任务组合起来的场景。

当前编辑器采用**分区表单**，不是自由连线的节点画布。流程主要由以下部分组成：

```text
来源路径 → 条件组合 → 文件操作 → 后置整理任务
```

:::caution[先预览再运行]
高级流程可以包含移动、覆盖、删除、加密、外部程序和云端传输等操作。请先在测试目录中配置少量文件，使用预览核对匹配范围，再运行或保存自动计划。
:::

## 快速创建流程

第一次使用时，建议从预设模板开始：

1. 进入 **文件整理 → 高级流程**。
2. 点击页面顶部的 **新建流程**图标按钮，打开独立的流程编辑窗口。
3. 展开 **默认规则**，选择“图片归档”“PDF 收集”“发票归档”等模板。
4. 将模板中的 `%USERPROFILE%` 路径改为测试目录，并检查目标目录。
5. 点击 **预览结果**，查看右侧文件列表和摘要。
6. 确认无误后点击 <span class="fluent-icon fluent-icon--save" aria-hidden="true"></span> **保存**，或 **保存并关闭**。

选择模板会先重置当前编辑器，再填入模板的来源、条件和操作。如果已经手动配置了内容，应先保存或导出，避免被模板覆盖。

## 复用已有整理任务

编辑窗口顶部的 **历史任务** 列表显示已有的普通[整理任务](/zh-cn/guide/task/)。选择一条任务后，应用会把它的名称、来源、文件规则、筛选条件、操作方式和目标路径载入流程主体。

:::caution[选择历史任务会替换主体配置]
复用普通任务会重置当前来源、条件和主体操作，但不会清除已经选择的后置整理任务。需要保留当前配置时，请先保存流程或导出 `.etrule`。
:::

复用后可以继续添加来源、条件和操作，因此它更适合把一条成熟的普通任务作为起点，而不是直接引用该任务本身。普通任务之后发生修改，不会自动同步到已保存的流程主体。

## 填写流程名称

编辑器中的 **描述** 输入框同时作为流程名称使用：

- 保存后，流程列表的“任务名称”会显示这里的内容。
- 状态栏也会使用该内容标识当前流程。
- 该项不能为空，否则不能保存。

建议使用能说明对象和结果的名称，例如“下载目录票据归档与备份”。

## 配置来源路径

“监控文件夹”区域至少需要一个有效来源。每个来源项提供：

- 路径输入框，可直接输入或拖入文件/文件夹路径；
- <span class="fluent-icon fluent-icon--folder-open" aria-hidden="true"></span> **选择文件夹**；
- <span class="fluent-icon fluent-icon--database" aria-hidden="true"></span> **路径别名**，可使用 `%Downloads%`、`%USERPROFILE%` 等别名；
- 二维码入口，用于显示局域网上传地址；
- 设置按钮，用于展开触发方式和子目录选项；
- <span class="fluent-icon fluent-icon--dismiss" aria-hidden="true"></span> **移除来源**。

点击区域标题旁的 <span class="fluent-icon fluent-icon--add" aria-hidden="true"></span> **添加**按钮可以加入多个来源。

### 来源触发方式

展开来源设置后可以看到三种模式：

| 界面模式 | 保存的配置 | 当前使用建议 |
| --- | --- | --- |
| **文件变更时触发** | 保存创建、删除、修改、重命名事件以及 1～3600 秒延迟 | 当前版本应在测试目录验证实际触发；不要仅凭列表中的“监控中”判断已建立工作流监控 |
| **定期轮询检查** | 将分钟或小时换算为间隔秒数保存 | 当前保存流程不会为该模式单独创建定期调度任务，暂不建议作为主要自动运行方式 |
| **定时计划（CRON）** | 保存 Quartz 兼容的六字段 CRON 表达式 | 保存时会创建工作流调度任务，是当前较明确的自动运行方式 |

需要稳定自动执行时，建议优先使用 **定时计划（CRON）**，并在保存后观察一次实际运行结果。暂停托盘中的全部监控时，文件监控和计划任务都会暂停；彻底退出 EasyTidy Pro 后也不会继续运行。

“包含子目录”决定扫描时是否进入下级目录。“在指定时间替换别名”用于确定日期类路径别名的解析时间，普通固定路径通常不需要修改。

### 二维码上传入口

点击二维码按钮会展开局域网上传区域，显示访问地址、二维码和启动方式。其他设备扫描后可把文件上传到当前来源目录。

- **按需启动**：需要使用时再启动接收服务。
- **立即启动**：展开或配置后立即准备接收。

只应在可信局域网中使用，并确认来源目录不会被危险流程自动删除、外传或覆盖。

## 设置执行顺序

“执行顺序”提供 **顺序执行** 和 **并行执行**：

- **顺序执行**：保存为串行模式，步骤按界面中的先后关系配置为“上一步成功后继续”。
- **并行执行**：保存为并行模式，步骤配置为始终执行。

:::note[当前版本的执行边界]
当前文件操作执行器仍会按生成后的操作映射逐项提交，因此“并行执行”不能作为严格并发保证。涉及移动、重命名、删除或多个步骤操作同一批文件时，应选择顺序执行，并通过预览和测试目录验证。
:::

## 添加条件

根条件组可以选择：

| 选项 | 行为 |
| --- | --- |
| **所有文件** | 忽略条件项，使用 `*` 匹配来源中的项目 |
| **满足任一条件** | 当前条件组内任意条件成立即可 |
| **满足全部条件** | 当前条件组内所有条件都必须成立 |

点击 <span class="fluent-icon fluent-icon--add" aria-hidden="true"></span> **添加条件** 创建条件项；点击 **添加条件组** 可以嵌套一组“全部”或“任一”判断。每个条件或条件组右侧的 <span class="fluent-icon fluent-icon--delete" aria-hidden="true"></span> **删除**按钮只删除该项。

### 可选条件字段

| 类别 | 字段 |
| --- | --- |
| 名称与类型 | 文件名、扩展名、文件类型、真实文件类型、文件夹名 |
| 大小与时间 | 大小、修改时间、创建时间、访问时间 |
| 内容与标签 | 文件内容、标签属性 |
| 系统属性 | 文件属性 |
| 图片分析 | 视觉特征 |

普通文本字段支持“是、不是、包含、不包含、匹配正则表达式、为空”等操作。大小和时间使用大于、小于、等于、区间等比较方式；文件内容可以选择包含文本、任意关键词、所有关键词、完全匹配或正则，并设置大小写和关键词顺序。

- **真实文件类型**依赖 Magika 组件，未安装时条件项内会显示下载入口。
- **文件内容**依赖文档内容提取组件，未安装时可在条件项内下载。
- **视觉特征**支持自动聚类、参考样板和文本标签；参考样板与文本标签模式需要 Pro。
- **标签属性**匹配 EasyTidy Pro 已保存的文件标签。

条件组会作用于所有主体操作，不是针对某一个步骤的独立条件。需要不同操作使用不同筛选范围时，应拆成多个流程或使用后置普通任务。

## 添加主体操作

“匹配的文件或文件夹”区域用于配置主体操作。点击标题旁的 <span class="fluent-icon fluent-icon--add" aria-hidden="true"></span> **添加**按钮可以增加操作项，每项包括操作方式、目标路径、专用参数和失败策略。

可选操作与普通整理任务基本一致，包括：

| 类别 | 操作 |
| --- | --- |
| 基础整理 | 移动、复制、重命名、添加标签、移除标签 |
| 压缩转换 | 压缩、解压、格式转换、提取结构化数据 |
| 安全处理 | 加密、解密、文件伪装（Pro） |
| 智能处理 | AI 分类、AI 总结、重复文件整理 |
| 链接与传输 | 文件快照、硬链接、软链接、云端传输、运行外部程序 |
| 清理 | 移至回收站、永久删除 |

标签、移除标签、格式转换和提取结构化数据不显示普通目标路径；云端上传也不显示本地目标路径。其他操作需要填写目标路径，目标框支持文件夹选择、拖放和路径别名。当前工作流校验可能还会要求部分不产生普通输出的操作填写目标路径，应以编辑器提示为准。

操作项按从上到下的创建顺序保存。当前界面没有主体操作的拖动排序；需要调整顺序时，可删除后按期望顺序重新添加。

选择 **文件伪装** 后，可以在“创建伪装文件”和“提取隐藏内容”之间切换。创建时可使用单个图片、音频、视频或自定义文件作为载体，也可以选择载体目录，并按随机、文件名或文件大小规则挑选载体；提取时会从伪装文件还原附加的原始内容。创建和提取都提供完成后删除来源的选项，首次配置时应保持关闭，并通过预览和测试文件验证输出。文件伪装只改变封装形式，不等同于加密。

### 失败策略

每个操作项底部可以选择：

- **继续下一任务**：记录失败并继续后续映射。
- **停止所有任务**：当前步骤失败后终止主体流程。
- **忽略错误**：降低该错误的日志级别并继续。
- **重试当前任务**：按当前重试策略尝试当前文件操作，重试用尽后继续后续映射。

失败策略作用于主体操作。后置整理任务是否在失败后继续，由后置任务区域的独立开关决定。

## 理解来源与操作的自动映射

高级流程不会自动把“步骤 1 的输出”作为“步骤 2 的输入”。执行时会根据来源数量和已配置操作数量建立路径映射：

| 来源数 | 操作数 | 实际映射 |
| --- | --- | --- |
| 1 | 1 | 一个来源执行一个操作 |
| 多个 | 1 | 每个来源都执行第一个操作 |
| 1 | 多个 | 同一个来源分别执行每个操作 |
| 多个且数量相同 | 多个 | 按界面顺序一对一配对 |
| 多个且数量不同 | 多个 | 每个来源分别执行每个操作 |

例如配置两个来源和两个操作时，默认是“来源 1 → 操作 1、来源 2 → 操作 2”，而不是两个来源都执行两个操作。数量不相同时才会形成多对多映射。

:::caution[主体操作不是输出接力]
如果第二步必须处理第一步生成的文件，请把第二步做成来源指向第一步输出目录的普通整理任务，并在“后置整理任务”中选择它；也可以拆成两个独立流程。不要仅依靠主体操作的显示顺序假设路径会自动传递。
:::

## 配置后置整理任务

“后置整理任务”会在所有主体操作完成后，按顺序运行已经存在的普通整理任务。

1. 使用搜索框按任务名称、分组或操作方式筛选。
2. 勾选需要执行的任务，已选任务会移动到列表前部。
3. 在已选任务之间拖动右侧排序手柄，调整执行顺序。
4. 根据需要勾选 **后置任务失败时继续执行后续任务**。

未勾选继续选项时，某个后置任务失败会停止后续任务并让流程报告失败；勾选后会继续运行其余后置任务，并在最后汇总失败。

后置任务保存的是普通任务 ID。如果对应普通任务后来被删除，编辑器会显示类似 `Task #ID` 的不可用记录，运行时也可能失败，应及时移除或重新选择。

## 预览、运行和停止

点击顶部的 **预览结果** 后，右侧提供两个视图：

- **文件列表**：显示文件名、类型、大小、修改时间和目标路径。
- **摘要**：显示匹配数量、操作类型数量、总大小和各操作的匹配分布。

预览不会修改文件。列表最多显示前 **500 条**匹配记录，但摘要总数会继续统计更多结果。

:::note[匹配数量可能大于实际文件数]
预览按“来源 × 操作”统计。一个文件同时匹配三个操作时，摘要可能计为三条操作匹配，而不是一个唯一文件。部分不使用普通目标路径的操作可能不会出现在当前预览分布中，应结合条件和实际测试判断。
:::

修改来源路径、目标路径、操作方式或条件后，旧预览会失效。点击 <span class="fluent-icon fluent-icon--play" aria-hidden="true"></span> **运行当前任务** 前必须重新预览；当前编辑器内容无需先保存也可以运行。

运行过程中可以点击 **停止运行**。停止请求会在当前操作检查取消状态时生效，正在进行的大文件压缩、外部程序或网络操作不一定立即结束。

## 保存、重置和分享

顶部菜单提供：

- <span class="fluent-icon fluent-icon--save" aria-hidden="true"></span> **保存**：保存后继续留在编辑窗口。
- <span class="fluent-icon fluent-icon--save" aria-hidden="true"></span> **保存并关闭**：保存并返回主窗口。
- <span class="fluent-icon fluent-icon--reset" aria-hidden="true"></span> **重置当前流程**：清空当前编辑状态并恢复一个空来源和空操作项。
- <span class="fluent-icon fluent-icon--share" aria-hidden="true"></span> **分享流程**：导出 `.etrule` 文件。
- <span class="fluent-icon fluent-icon--import" aria-hidden="true"></span> **导入流程**：只接受包含高级流程的 `.etrule` 分享包，并创建一条新流程。
- **AI 生成规则**：根据自然语言填写来源、条件和操作，属于 Pro 功能；生成后仍需手动检查路径和危险操作。

保存至少要求填写名称、一个有效来源和一个已配置操作。添加标签必须填写标签；大多数操作必须填写目标路径。涉及系统目录时还会显示安全确认。

导入和分享会尽量使用路径别名，但不会替你验证目标机器上的目录、云端节点、组件、AI 模型或外部程序。只导入可信来源的规则。

## 管理流程列表

流程列表每行提供 <span class="fluent-icon fluent-icon--edit" aria-hidden="true"></span> **编辑**、<span class="fluent-icon fluent-icon--delete" aria-hidden="true"></span> **删除** 和 <span class="fluent-icon fluent-icon--play" aria-hidden="true"></span> **运行**。双击某行的非操作区域也会执行该流程；落在编辑、删除、运行按钮上的双击仍由按钮处理。执行期间状态列显示旋转动画，完成后恢复为状态图标。

状态列使用图标和颜色表示空闲、运行、错误或已禁用。监控状态列会汇总来源数量、标记为监控的来源数、子目录和延迟信息；该文字是保存配置的摘要，不代表对应后台触发器一定已经成功运行。

在“全部分组”视图下，每行流程名称下方会显示一行灰色小字分组名（带文件夹小图标），筛选到具体分组后自动隐藏。

运行、批量操作、切换分组、删除等操作都会通过主窗口底部的提示条反馈结果，包括失败原因和部分失败的数量。

### 分组管理

- 打开顶部的分组选择器，点击 **分组管理**，在弹窗中新增、重命名、排序或删除自定义分组。
- 分组名称不能重复；新建或重命名为已有名称时，应用会提示修改。
- 新建分组的输入框支持回车保存，新分组排在最后；拖动每个分组前的手柄可以调整顺序，松开自动保存。
- 分组名默认只读，点击 **重命名** 才能编辑：回车或 **保存** 提交，`Esc` 取消并还原。
- “全部分组”和“未分组”是固定保留的内置项，不能重命名或删除；新建流程默认进入“未分组”。
- 删除自定义分组时，组内流程会移动到“未分组”，流程本身不会删除。
- <span class="fluent-icon fluent-icon--play" aria-hidden="true"></span> **执行分组**需要先选择具体分组，不能直接对“全部分组”执行。
- 切换分组后会弹出提示，显示已切换到的分组名以及该分组下的流程数量。

### 勾选与批量操作

批量操作以复选框勾选为准。勾选方式与整理任务列表一致：表头复选框全选或清空，**反选** 按钮翻转全部勾选状态，`空格` 只翻转当前焦点行，`Shift` + 单击勾选连续范围，`Ctrl + A` 全选。行的蓝色高亮为“已勾选条目 ∪ 当前焦点行”，切换分组、切换页签或切到其他应用再切回都不会丢失已勾选项的高亮。右键菜单作用于已勾选项，或在右击未勾选行时只作用于该行。完整说明见[整理任务的勾选与批量选择](/zh-cn/guide/task/#勾选与批量选择)。

勾选多条流程后，批量栏提供：

- <span class="fluent-icon fluent-icon--play" aria-hidden="true"></span> **立即运行**；
- <span class="fluent-icon fluent-icon--checkmark" aria-hidden="true"></span> **启用**；
- **移动到分组**；
- <span class="fluent-icon fluent-icon--delete" aria-hidden="true"></span> **删除**。

批量运行和分组运行内部按列表顺序逐条执行所选流程。

新建流程会添加到列表末尾。工作流列表不显示数据库 ID，识别流程时应以名称和分组为准。

## 免费版配额与 Pro 功能

当前工作流策略为：

- 免费版提供 **10 次成功保存配额**；新建和编辑后保存都会计入。
- 免费版提供 **10 次执行配额**；运行当前流程、运行列表流程、批量运行或执行分组都会使用执行配额。
- 批量运行或执行一个分组按一次命令记录配额，而不是按其中每条流程分别记录。
- Pro 用户的流程保存和执行不受这两项免费次数限制。
- AI 生成规则、视觉样板/文本标签分类、深度语义理解等功能还有各自的 Pro 限制。

预览、打开编辑器、查看列表、分组管理和编辑配置本身不会消耗保存或执行配额；只有成功保存或通过权限检查执行时才记录。

## 常见问题

### 点击运行当前任务时提示先预览

这是正常的安全限制。点击 **预览结果**，等待预览完成后再运行。修改来源、目标、操作或条件会使预览失效，需要重新预览。

### 配置了两个来源和两个操作，为什么没有全部执行

两个来源与两个操作数量相同时会按顺序一对一配对。需要每个来源执行每个操作时，可以拆分流程，或调整来源/操作组织方式并通过预览确认映射。

### 第二个操作没有处理第一个操作的输出

主体操作共享流程来源，不会自动接力前一步的目标目录。把下一步做成普通整理任务，并将第一步输出目录设为它的来源，然后添加为后置整理任务。

### 预览数量比文件数量多

同一文件命中多个操作时，每个“文件 × 操作”组合都会计入匹配总数。查看操作分布和文件列表，判断是否属于重复统计。

### 选择历史任务后，刚才的配置不见了

历史任务和预设模板都会替换当前主体配置。未保存内容无法自动恢复；重新配置，或从先前导出的 `.etrule` 导入。

### 文件变更或定期轮询没有自动执行

当前保存逻辑会为 CRON 来源创建明确的计划任务，文件变更和定期轮询配置不应直接视为已经建立稳定调度。建议改用 CRON，保存后保持应用在托盘运行，并通过[运行日志](/zh-cn/guide/logs/)检查实际触发记录。

### 后置任务显示 `Task #数字`

原普通整理任务可能已经被删除。取消选择该记录，并从当前可用任务列表重新选择。否则运行到该后置任务时可能失败。

### 保存时提示目标路径缺失

检查每个主体操作。标签、移除标签、格式转换、结构化提取和云端上传通常不显示普通目标路径；其他操作应填写目标路径。当前版本对部分无普通输出的操作仍可能执行统一路径校验，请按界面提示补充测试路径并预览。

普通单步骤整理请参阅[整理任务](/zh-cn/guide/task/)，条件字段的大小、时间、属性和内容含义可结合[筛选条件](/zh-cn/guide/filter/)理解，运行错误可在[运行日志](/zh-cn/guide/logs/)中查看。
