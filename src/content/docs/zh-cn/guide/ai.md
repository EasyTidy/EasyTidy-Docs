title: AI 服务
description: 配置 EasyTidy Pro 的在线与本地 AI 模型，并使用 AI 分类、摘要、结构化提取、语义模型和视觉分类。
---

EasyTidy Pro 的 AI 能力分为三类：调用大语言模型（LLM）的文件处理、本地 Embedding 语义分类，以及本地视觉模型分类。基础文件整理不依赖 AI；不使用这些功能时，可以跳过本页中的全部配置。

## 功能与前置条件

| 功能 | 主要用途 | 前置条件 |
|---|---|---|
| AI 分类 | 根据自然语言要求或分类标签生成移动、复制等整理计划 | 默认 LLM；启用深度语义理解时还需要本地 Embedding 模型 |
| AI 总结 | 提取文件内容、生成摘要并输出 PDF | 默认 LLM、内容提取组件 |
| 提取结构化数据 | 按指定字段从文档中提取数据，输出 JSON、CSV 或 Excel | 默认 LLM、内容提取组件 |
| 智能规则助手 | 根据自然语言生成整理规则或高级流程 | 默认 LLM；部分能力需要 Pro |
| 视觉特征分类 | 根据图片外观进行样板匹配、自动聚类或文本标签分类 | 本地视觉模型；部分模式需要 Pro |
| 深度语义理解 | 识别近义词和上下文，提高文本分类准确率 | 本地 Embedding 模型、Pro |
| 智能文件识别 | 根据文件内容识别真实类型，不依赖扩展名 | Magika 组件 |
| OCR 与文档解析 | 从图片、扫描版 PDF 等文件中提取文字 | 内容提取组件；MinerU 为可选云端服务 |

:::caution[先确认数据边界]
在线 LLM 会接收完成任务所需的文件名、提取文本、分类要求或其他上下文。MinerU 云端 OCR 可能上传完整文件。首次添加 AI 操作时，EasyTidy Pro 会显示隐私提示；请先阅读所用服务商的隐私政策，不要把不适合离开本机的敏感数据发送到远程服务。
:::

## 准备 AI 组件

进入 **设置 → 组件设置**，根据任务安装或启用以下组件：

- **智能文件识别**：使用 Google Magika 分析文件内容，可识别 200 多种文件类型。“真实文件类型（AI）”条件需要该组件。
- **内容提取**：从 PDF、Word、Excel、图片等文件中读取文本。AI 总结、结构化提取和内容感知分类可能使用该组件。

组件未安装、文件损坏或当前格式不受支持时，应用会跳过相应分析，或回退到只使用文件名、扩展名等基础信息。具体原因可以在“运行日志”中查看。

如果需要云端 OCR，可在 **集成设置 → MinerU** 配置。MinerU 启用后会优先解析支持的文档，失败或超时后再回退到可用的本地 OCR 路径。

## 配置大语言模型

进入 **设置 → AI 模型设置**。该页面包含模型配置、Embedding 向量模型和视觉智能分类三个区域。

### 支持的提供方

EasyTidy Pro 当前支持以下提供方类型：

| 类型 | 提供方 |
|---|---|
| 内置在线服务 | OpenAI、阿里百炼、Hugging Face、Gemini、DeepSeek、Anthropic、文心一言、Azure OpenAI、腾讯混元、火山引擎、讯飞星火 |
| 兼容接口 | OpenAI 兼容格式、Anthropic 兼容格式 |
| 本地服务 | Ollama |
| 本地模型 | Phi-4-mini、本地 ONNX 模型 |

“OpenAI 兼容格式”适用于实现 OpenAI 风格接口的第三方服务或自建网关；“Anthropic 兼容格式”适用于实现 Anthropic Messages API 的代理或中转服务。兼容并不代表所有扩展参数都受支持，模型必须能够稳定返回任务要求的结构化结果。

### 配置字段

| 字段 | 说明 |
|---|---|
| 显示名称 | 仅用于在 EasyTidy Pro 中区分配置，例如“本地 Ollama”或“工作用 DeepSeek” |
| 提供方 | 决定接口协议、默认地址和需要显示的认证字段 |
| 模型标识 | 服务商使用的模型名称或部署名称，例如 Ollama 中已拉取的模型名 |
| 基础地址 | 兼容接口、自定义区域、远程 Ollama 或代理服务的 HTTP/HTTPS 地址 |
| 应用 ID | 文心一言、腾讯混元、火山引擎等提供方需要的额外标识 |
| 接口密钥 | 在线服务的 API Key；本地 Ollama、Phi-4-mini 和本地 ONNX 模型不要求此项 |
| 模型目录 | Phi-4-mini 或 ONNX GenAI 模型所在的本地目录 |
| 温度 | 控制输出随机性，范围为 0 到 2；分类和结构化任务建议使用较低值 |
| 默认模型 | AI 分类、总结和结构化提取等默认 AI 操作使用的模型 |

:::note[服务地址]
大多数内置提供方会自动填写默认地址。阿里百炼、Azure OpenAI、Ollama、OpenAI 兼容格式和 Anthropic 兼容格式允许填写自定义地址。区域、部署名和路径规则以对应服务商为准。
:::

### 添加并设为默认模型

1. 打开 **设置 → AI 模型设置**。
2. 展开“模型配置”，点击 **新建模型**。
3. 填写显示名称并选择提供方。
4. 填写模型标识、服务地址和界面要求的认证信息。
5. 将温度设置为适合任务的值；分类任务可从 `0.2` 到 `0.5` 开始测试。
6. 勾选“将此模型设置为默认模型”，然后保存。
7. 在少量测试文件上创建 AI 分类或 AI 总结任务，确认连接和输出正常。

可以保存多个提供方，但任何依赖 LLM 的操作都必须存在一个默认模型。删除当前默认模型前，应先把另一个配置设为默认。

### 配置 Ollama

1. 在本机安装并启动 Ollama，确认服务可以访问。
2. 使用 Ollama 拉取所需模型。
3. 在 EasyTidy Pro 中选择 **Ollama**。
4. 基础地址默认是 `http://localhost:11434`；远程部署时填写实际地址。
5. “模型标识”必须与 Ollama 中的模型名称一致。

Ollama 本身不要求 API Key，但远程反向代理可能有额外鉴权要求。EasyTidy Pro 当前的 Ollama 配置不会显示 API Key 字段，带认证的网关应改用合适的兼容接口类型。

### 配置本地 ONNX 模型

选择 **Phi-4-mini** 或 **本地 ONNX 模型** 后，界面会要求选择模型目录，不再要求模型标识、服务地址或 API Key。

- 模型目录必须是可由 ONNX Runtime GenAI 直接加载的完整模型目录，而不是单个 `.onnx` 文件。
- 本地模型必须使用 ONNX Runtime GenAI 可加载的目录结构，并与服务使用的对话模板兼容；仅有一个普通 ONNX 文件并不足以运行生成任务。
- 本地生成模型通常需要较多内存和磁盘空间，首次加载耗时也可能明显高于在线接口。
- 本地模型的输出能力取决于模型规模。AI 分类和结构化提取要求模型严格返回结构化内容，小模型可能更容易出现空结果或格式错误。

## 配置 Embedding 向量模型

Embedding 模型在本机把文件描述和分类标签转换成向量，用于“深度语义理解”。它能识别“发票”和“报销单”这类语义相近的表达，并减少每个文件都调用 LLM 的次数。

当前可选模型如下：

| 模型 | 语言与特点 | 向量维度 |
|---|---|---:|
| BGE-Small-ZH v1.5 | 中文优化，适合中文文件分类 | 512 |
| GTE-Small | 轻量英文模型，仅建议用于英文内容 | 512 |
| MiniLM-L12-v2 | 多语言通用模型，体积和效果较均衡 | 384 |
| Piccolo-Base-ZH | 中文模型，维度较高 | 768 |
| BCEmbedding | 跨语言检索与语义匹配 | 512 |
| Qwen3-Embedding-0.6B | 多语言、1024 维，质量更高但资源占用较大 | 1024 |

### 下载与启用

1. 打开 **设置 → AI 模型设置 → Embedding 向量模型**。
2. 根据主要文件语言和设备资源选择模型。
3. 点击 **下载模型**，等待状态变为“已就绪”。
4. 创建 AI 分类任务，并打开“深度语义理解”。

模型默认保存在程序目录下的 `models` 文件夹。下载过程会访问 Hugging Face；下载失败时，应用会显示手动下载地址和目标路径。主模型和标记为必需的附加文件必须全部放到提示的目录中。

:::note[Embedding 与 LLM 的关系]
Embedding 推理在本机完成，但它不一定让整个任务完全离线。Pro 多策略分类会优先使用本地向量；低置信度文件仍可能交给已配置的默认 LLM 复核。未配置可用 Embedding、模型加载失败或选择“强制 LLM”时，任务会回退到 LLM 分类。
:::

## 配置视觉智能分类

视觉智能分类通过本地 ONNX 模型分析图片内容，不依赖文件名。当前提供以下模型：

| 模型 | 特点 |
|---|---|
| DINOv3 ViT-S/16 | 384 维图像特征，适合样板匹配和自动聚类 |
| SigLIP2 Base | 768 维图文双编码器，支持自定义文本标签 |
| SigLIP2 Large | 1024 维，精度更高、模型更大 |
| SigLIP2 SO400m | 1152 维，资源占用最高 |

### 三种分类模式

- **参考样板目录**：将样板图片按类别放进子文件夹，子文件夹名就是分类标签。该模式需要 Pro。
- **自动聚类**：系统会自动将相似的图片分组到不同的文件夹，方便您浏览和管理。
- **分类标签**：输入“合同、发票、截图”等文本标签，让 SigLIP2 比较图片与标签的相似度。该模式只适用于包含文本塔的 SigLIP2 模型，并需要 Pro。

样板目录示例：

```text
D:\ImageTemplates\
├── 发票\
│   ├── sample-01.jpg
│   └── sample-02.png
├── 截图\
│   └── sample-01.png
└── 风景\
    └── sample-01.jpg
```

### 启用步骤

1. 打开 **设置 → AI 模型设置 → 视觉智能分类**。
2. 选择视觉模型并下载，等待模型状态变为“已就绪”。
3. 启用“视觉语义识别”。
4. 选择分类模式。
5. 使用样板模式时，添加一个或多个样板根目录并点击 **更新特征**。
6. 使用自动聚类时，点击 **更新自动聚类缓存**，或在执行时由应用按源目录生成缓存。
7. 在任务规则中选择“视觉特征”条件，并配置模式、样板或文本标签。

当视觉结果低于阈值、前两名过于接近或模型无法处理图片时，应用可能使用 OCR 辅助判断，或把自动运行中的低置信度项目送入“待确认”。视觉分类只处理可读取的图片；损坏文件、权限不足或不支持的图像会被跳过。

## 使用 AI 分类

AI 分类先生成文件操作计划，再由用户确认执行。应用会校验 AI 返回的源路径、过滤不存在的文件，并对不安全路径进行拦截。

### 创建分类任务

1. 进入 **文件整理 → 整理任务**，新建或编辑任务。
2. 设置源文件夹、基础匹配规则和目标根目录。
3. 将操作方式设为 **AI 分类**。
4. 选择输入方式：
   - **自然语言描述**：直接描述类别、处理方式和判断依据。
   - **标签匹配**：输入多个分类标签，按回车或逗号确认。
5. 如已下载 Embedding 模型并拥有对应权限，可启用“深度语义理解”。
6. 保存任务并执行预览。
7. 在 AI 分类预览中逐项检查分类理由、操作类型和目标路径，取消不需要的项目或直接修改建议。
8. 确认后再执行文件操作。

自然语言示例：

```text
把文件分成“合同”“发票”“会议资料”和“其他”四类。
优先根据文件内容判断；无法确定时放入“其他”，不要删除任何文件。
```

标签匹配示例：

```text
合同, 发票, 报销单, 项目计划, 其他
```

:::caution[必须检查预览]
LLM 可能误判分类、建议错误目录或返回不完整结果。AI 分类预览允许修改操作和目标路径；重要文件应先使用“复制”或在测试目录验证，不要把 AI 结果当作无需复核的最终决定。
:::

### 分类执行路径

- 未启用 Pro 多策略分类，或手动强制使用 LLM 时，任务直接使用默认 LLM 分类。
- 启用深度语义理解后，应用会尝试本地预处理、Embedding 分类和缓存；低置信度结果再由 LLM 复核。
- Embedding 模型不可用时，任务自动回退到默认 LLM。
- 没有默认 LLM 且任务需要 LLM 兜底时，任务会提示“未设置默认 AI 服务”。

## 使用 AI 总结

AI 总结会先在本机提取文件内容，再将需要总结的文本交给默认 LLM，最后在目标目录生成 PDF。

1. 确认内容提取组件可用，并配置默认 LLM。
2. 新建任务，将操作方式设为 **AI 总结**。
3. 选择内置提示词，或填写自定义 System Prompt 和 User Prompt。
4. 设置源文件、目标目录和筛选条件。
5. 先用单个测试文件执行，检查日志和生成的 PDF。

输出文件名包含“AI总结”、时间戳和原文件名。无法提取文本、模型返回空内容或目标目录不可写时，不会生成有效摘要文件。

## 提取结构化数据

“提取结构化数据”适合从合同、发票、订单或表格中提取固定字段。每个源文档生成一个输出文件。

1. 新建任务，将操作方式设为 **提取结构化数据**。
2. 输入字段，例如“客户姓名、订单号、金额、签订日期”。
3. 选择 JSON、CSV 或 Excel 输出格式。
4. 选择输出目录；留空时输出到源文件所在目录。
5. 处理敏感内容时，可启用“发送给 AI 前对敏感数据脱敏”。
6. 使用少量代表性文档测试字段完整性和格式。

脱敏在本机将邮箱、手机号、证件号等内容替换为占位符，并在提取结果中尝试还原。该选项默认关闭，因为某些提取任务需要真实字段值。免费版当前单次最多处理 5 个文件，超出部分会被跳过；以界面显示的授权策略为准。

## 使用智能规则助手

高级流程中的“用 AI 生成规则”可以把自然语言转换成筛选条件和操作步骤。例如：

```text
把下载目录中最近 7 天的 PDF 和 Word 文档复制到 D:\Work\Recent，
然后按修改日期创建子目录。
```

助手会先尝试本地解析；本地结果置信度不足时，可以使用所选 LLM 增强。生成结果必须检查后再应用。多步骤请求可能转换为高级流程，而不是单个整理任务。该能力带有 Pro 标识时，需要相应授权。

## 隐私、费用与本地运行

- **在线提供方**：可能接收文件名、路径片段、提取文本、提示词和任务上下文，并产生服务商侧费用。
- **Ollama 与本地 ONNX**：模型推理可以在本机完成；远程 Ollama 地址仍属于远程服务。
- **Embedding 与视觉模型**：推理和向量缓存在本机完成，首次下载模型时需要联网并占用额外磁盘空间。
- **Magika**：安装组件后在本机识别文件真实类型。
- **MinerU**：属于云端文档解析服务，启用后可能上传完整文件。
- **更新与授权**：即使 AI 推理完全本地，应用的更新检查和授权验证仍可能访问网络。

API Key、Token、模型地址和日志可能包含敏感信息。截图、导出配置或提交问题前，请先移除密钥、私人路径和文件内容。

## 常见问题

### 提示“未设置默认 AI 服务”

进入 **设置 → AI 模型设置**，确认至少保存了一个模型，并在模型列表或编辑区域将其设为默认。仅下载 Embedding 或视觉模型不能替代默认 LLM。

### 在线模型连接失败

依次检查 API Key、模型标识、基础地址、区域或 Azure 部署名、账户余额、服务商限流和系统代理。兼容接口还应确认协议类型正确：OpenAI 风格接口选择“OpenAI 兼容格式”，Anthropic Messages API 选择“Anthropic 兼容格式”。

### Embedding 或视觉模型下载失败

先检查磁盘空间、程序目录写入权限和网络连接。下载失败提示会提供 URL 与保存路径；手动下载时必须保留要求的文件名，并把主模型及必需附加文件放到同一模型目录。完成后重新进入 AI 设置页检查状态。

### AI 分类没有结果或全部进入“其他”

确认源文件确实被基础规则匹配，目标目录有效，分类描述中包含明确类别。内容分类还需要可用的内容提取组件。使用 Embedding 时，检查模型状态、标签语言和置信度；分类标签过于相似也会降低区分度。

### AI 总结或结构化提取没有输出

先在“运行日志”中检查是否成功提取文本。扫描版 PDF 或图片可能需要 OCR；文件加密、格式不支持、内容为空、目标目录不可写或模型未按要求返回内容都会导致无输出。

### 本地模型很慢或内存占用较高

首次加载模型通常最慢。优先选择较小的 Embedding、视觉或生成模型，减少单批文件数量，并避免同时运行多个模型密集型任务。Qwen3 Embedding、SigLIP2 Large/SO400m 和大型 ONNX 生成模型对内存与 CPU 的要求更高。

更多任务、规则和排错说明请参阅[任务编排](/zh-cn/guide/task/)、[高级规则](/zh-cn/guide/filter/)和[常见问题](/zh-cn/faq/)。
